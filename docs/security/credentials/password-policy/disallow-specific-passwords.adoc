This describes how to prevent users from setting specific passwords to increase security in your deployment.

== Introduction

To enhance security, you can define various limitations for passwords, such as minimal length, character uniqueness, etc.
For more details on this subject, see xref:/midpoint/reference/security/credentials/password-policy/[].

However, sometimes you may also want to define a set of specific words that you do not want to be used as passwords.
This is useful because users might use passwords that comply with the defined password policies, but may not be safe enough because they are easily guessed by potential attackers.

This is typically relevant for values that are:

* Related to your environment, such as values of `CompanyName` or `ProductName`.
* Widely known or leaked passwords, such as `12345678` or `Password1234`.

You can use a xref:/midpoint/reference/security/credentials/password-policy/#check-expression[check expression] to list such values and thus prevent them from being used as passwords.

== Disallow passwords

In typical environments, there are various password policies that define how passwords may be constructed, i.e., how long or complicated they must be.
This is implemented using xref:/midpoint/reference/security/credentials/password-policy/#value-policy[value policies].

To further enhance the rules for passwords, you can use xref:/midpoint/reference/security/credentials/password-policy/#check-expression[check expressions] that function as filters that only accept password values if the expressions return `true`.

For increased security, you can define a set of values that cannot be used as passwords.
This is done by extending check expressions with the following comma-separated definition holding values that you want to block:

`def forbidden = ["value1", "value2", "value3", ... ]`

As a result, users will not be able to define passwords that are listed in this definition.

In the example below, we use an expression that disallows not only values of `FamilyName`, `GivenName`, and `AdditionalName`, but also the specific values `Example company`, `Wonderful product`, `1234`, `12345678`, and `Password1234`.

.Example check expression that disallows password values
[source,xml]
----
<stringPolicy>
        <limitations>
            ...
            <checkExpression>
                <expression>
                    <script>
                        <code>
                            import com.evolveum.midpoint.xml.ns._public.common.common_3.UserType

                            def forbidden = ["Example company", "Wonderful product", "1234", "12345678", "Password1234"]

                            if (object instanceof UserType) {
                                return !basic.containsIgnoreCase(input, object.getName())
                                &amp;&amp; !basic.containsIgnoreCase(input, object.getFamilyName())
                                &amp;&amp; !basic.containsIgnoreCase(input, object.getGivenName())
                                &amp;&amp; !basic.containsIgnoreCase(input, object.getAdditionalName())
                             } else {
                                 return true
                             }
                         </code>
                     </script>
                </expression>
                <failureMessage>The password must not contain username, family name and given name and additional names.</failureMessage>
            </checkExpression>
            ...
        </limitations>
    </stringPolicy>
----
