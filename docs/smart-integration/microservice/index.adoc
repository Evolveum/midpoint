== Overview

The *Smart Integration microservice* is a separate service that provides the AI part of the xref:../recommendations/index.adoc[smart recommendations].
MidPoint prepares the data for a recommendation (for example the object class schema or statistics), sends it to the microservice, and processes the result.
The microservice builds prompts from the data, calls a large language model (LLM) and returns a structured response.

The microservice is written in Python and built on FastAPI.
It runs in the Hypercorn server and uses LangChain to call the LLM.

== Architecture

.Communication between midPoint, the microservice and the LLM
----
midPoint ── HTTP/JSON ──→ Smart Integration microservice ──→ LLM provider
                                                  │
                                                  └──→ Langfuse (optional tracing)
----

* *MidPoint* calls the microservice whenever a recommendation needs AI.
The calls are made by the service client in the `smart-impl` module.
* *Smart Integration microservice* has no database.
It processes each request independently, using only the data in the request.
* *LLM provider* is any service with an OpenAI-compatible chat API, for example OpenRouter or a self-hosted model.
* *Langfuse* receives traces of requests and LLM calls when tracing is enabled, see xref:logging.adoc[].

== Communication with midPoint

MidPoint communicates with the microservice using HTTP and JSON:

* Recommendation operations are `POST` requests under the `/api/v1` base path, for example `/api/v1/focusType/suggestFocusType`, see xref:endpoints/index.adoc[].
* The health check is a `GET /health` request.
MidPoint uses it to get the AI provider name and model shown in the GUI.

The connection is configured in the `<smartIntegration>` container of the system configuration, see xref:../configuration.adoc[]:

[cols="35%,65%",options="header"]
|===
| Setting | Description

| `serviceUrl`
| URL of the microservice.
It can be overridden by the `midpoint.smartIntegration.serviceUrlOverride` system property.

| `serviceApiKey`
| API key sent in the `X-Gravitee-Api-Key` header of every request.
The microservice itself does not check the key.

| `serviceResponseTimeout`
| Maximum time midPoint waits for a response, 120 seconds by default.
The microservice has its own timeout for LLM calls, see xref:configuration.adoc[].
|===

Item paths and type names in requests use a shortened format, see xref:../service-item-paths.adoc[].

MidPoint records the communication with the microservice in the audit trail, see xref:../security/auditing-logging.adoc[].
