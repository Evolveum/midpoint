== Overview

*Smart recommendations* help the user configure a resource.
midPoint analyzes the resource schema and sample data, optionally with the help of the AI microservice, and proposes parts of the resource configuration.

Recommendations are never applied automatically.
The user reviews them in the GUI and decides which of them to accept.

== Types of recommendations

[cols="25%,75%",options="header"]
|===
| Recommendation | Description

| Object types
| Proposes resource object types (kind, intent and delineation) for a given object class, see xref:object-types/object-types-recommendation.adoc[Smart object types recommendation].

| Focus type
| Proposes the focus type (for example, user or role) that corresponds to a resource object type, see xref:focus-type/focus-type-recommendation.adoc[Smart focus type recommendation].

| Correlation
| Proposes correlation rules that link resource objects to existing focus objects, see xref:correlation/correlation-recommendation.adoc[Smart correlation recommendation].

| Mappings
| Proposes inbound or outbound attribute mappings for a resource object type, see xref:mappings/mappings-recommendation.adoc[Smart mappings recommendation].

| Associations
| Proposes associations between resource object types, see xref:associations/associations-recommendation.adoc[Smart associations recommendation].

| Synchronization
| Proposes synchronization rules for a resource object type, without the AI microservice, see xref:synchronization/synchronization-recommendation.adoc[Smart synchronization recommendation].
|===

== Common principles

* **Background operation.** A recommendation is computed by a background task.
Submitting the operation returns a token that is used to check its status and to get the result.
* **Authorization.** Recommendation operations require the `#smartIntegration` authorization, see xref:../security/authorization.adoc[].
* **Data access permissions.** The user decides what data may be sent to the AI microservice.
* **Sample data.** Correlation and mappings recommendations are validated on sample resource objects, see xref:../shadow-sampling.adoc[].

== Schema match

Mappings and correlation recommendations start from a *schema match* - a list of pairs that say which resource attribute corresponds to which focus property.
The pairs come from predefined well-known schemas (LDAP, Active Directory, SCIM) and, with `SCHEMA_ACCESS`, from the AI microservice.
The schema match is stored in the repository and reused until it expires.
See xref:../schema-match.adoc[Schema match].
