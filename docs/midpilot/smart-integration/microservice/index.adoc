== Overview

The *Smart Integration Microservice* is the implementation of Smart Integration AI Service, that provides the AI part of the xref:../recommendations/index.adoc[smart recommendations].
MidPoint prepares the data for a recommendation (for example the object class schema or statistics), sends it to the microservice (either self-hosted or hosted by Evolveum), and processes the result.
The microservice builds prompts from the data, calls a large language model (LLM) and returns a structured response.

NOTE: Smart Integration AI Service is a term used in general for the service outside midPoint, which serves the APIs necessary for the Smart Recommendations.
The term Smart Integration Microservice refers to a particular implementation of the AI service.
This text is mostly about the Microservice, but some aspects applies also in broader context of the AI Service (e.g. the `serviceApiKey` configuration).

NOTE: In this text we will refer to the "Smart Integration Microservice" simply as "the microservice".

The microservice is written in Python and built on FastAPI.
It runs in the Hypercorn server and uses LangChain to call the LLM.

== Architecture

.Communication between midPoint, the microservice and the LLM
----
midPoint ── HTTP/JSON ──→ Smart Integration microservice ──→ LLM provider
                                                  │
                                                  └──→ Langfuse (optional tracing)
----

* *MidPoint* calls the microservice (AI service in general) whenever a recommendation needs AI.
* *Smart Integration Microservice* has no database.
It processes each request independently, using only the data in the request.
* *LLM provider* is any service with an OpenAI-compatible chat API, for example OpenRouter or a self-hosted model.
* *Langfuse* receives traces of requests and LLM calls when tracing is enabled, see xref:logging.adoc[].

MidPoint communicates with the microservice using HTTP and JSON:

* Recommendation operations are `POST` requests under the `/api/v1` base path, for example `/api/v1/focusType/suggestFocusType`, see xref:endpoints/index.adoc[].
* The health check is a `GET /health` request.
MidPoint uses it to get the AI provider name and model shown in the GUI.


== MidPoint side configuration

The connection details are configured in the `<smartIntegration>` container of the system configuration, see xref:../configuration.adoc[]:

[cols="35%,65%",options="header"]
|===
| Setting | Description

| `serviceUrl`
| URL of the microservice (AI service in general).
It can be overridden by the `midpoint.smartIntegration.serviceUrlOverride` system property.

| `serviceApiKey`
| API key sent in the header of every request.
The microservice itself does not check the key.
But in broader context of AI service, it can be used, (and it is by Evolveum's hosted AI Service) e.g. for authentication.

| `serviceResponseTimeout`
| Maximum time midPoint waits for a response, 120 seconds by default.
The microservice has also its own timeout for LLM calls, see xref:configuration.adoc[].
|===

== Data sent to the LLM

The AI service passes the data from the request to the LLM provider as part of the prompts.
Which data midPoint sends depends on the data access permissions granted to the operation, see xref:../security/data-access-permissions.adoc[].

Item paths and type names in requests use a shortened format, see xref:../service-item-paths.adoc[].

MidPoint records the communication with the AI service in the audit trail, see xref:../security/auditing-logging.adoc[].
